DECLARACIÓN FUNDAMENTAL SOBRE LA NATURALEZA DEL SOFTWARE

El sistema Torre Residencial Jardines del Cerro IV es un software 100% basado en la web (Software as a Service - SaaS) y alojado en la nube.
Esto significa que los usuarios finales (compradores, propietarios, inquilinos y personal de administración) NO REQUIEREN INSTALAR NINGÚN TIPO DE PROGRAMA, EJECUTABLE (.EXE), DRIVER O BASE DE DATOS LOCAL en sus computadoras, laptops, tablets o teléfonos inteligentes. El acceso se realiza exclusivamente a través de un navegador web moderno utilizando la dirección URL pública protegida con protocolo HTTPS:
https://jardines-del-cerro-976758200291.us-central1.run.app/

La plataforma fue diseñada bajo una arquitectura moderna desacoplada que combina una capa de servicios API RESTful construida con FastAPI (Python 3.11) y un cliente frontend responsivo e interactivo implementado con estándares web modernos (HTML5, CSS3, JavaScript ES6+ y Bootstrap 5), complementado con servicios cognitivos de Google Gemini AI y servicios fiscales certificados ante la DGII.

2. Método Oficial: Despliegue en la Nube (Google Cloud Platform)

El método oficial y definitivo utilizado para la puesta en producción del sistema de la Torre Residencial Jardines del Cerro IV es la arquitectura Serverless de Google Cloud Run en la región us-central1 (Iowa, EE. UU.). Este modelo garantiza alta disponibilidad (SLA 99.95%), tolerancia a fallos, certificados SSL/TLS automáticos y costo de infraestructura de $0.00 USD durante períodos de inactividad gracias a su capacidad de escalar a cero instancias.

2.1 Arquitectura Serverless con Google Cloud Run

En producción, Cloud Run recibe el tráfico web entrante mediante balanceadores de carga globales de Google, finaliza el túnel HTTPS cifrado con TLS 1.3 y entrega las solicitudes al contenedor en el puerto interno 8080 (definido en la variable $PORT).

Figura 2.1: Despliegue activo y operativo del sistema en producción sobre Google Cloud Run.

2.2 Contenedor Docker y Google Artifact Registry

La aplicación se empaqueta en una imagen de contenedor Docker optimizada y se almacena en el registro corporativo seguro: 

us-central1-docker.pkg.dev/jardines-del-cerro-514416/cloud-run-source-deploy/jardines-del-cerro

El archivo Dockerfile de producción consta de los siguientes pasos fundamentales: 

FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
ENV PORT=8080
EXPOSE 8080
CMD ["uvicorn", "sitio_web.backend.main:app", "--host", "0.0.0.0", "--port", "8080"]
Figura 2.2: Configuración del contenedor en la consola de Google Cloud Run e integración con Artifact Registry.
Aviso Crítico de Implementación Automática: Como indica la advertencia de Google Cloud en la Figura 2.2, las imágenes de contenedor se implementan automáticamente mediante el activador de Cloud Build. Si se modifica o despliega una imagen de forma manual en la consola, dicha configuración será sobreescrita la próxima vez que se realice un commit en GitHub y se active el pipeline de CI/CD.

2.3 Pipeline de Integración y Entrega Continua (CI/CD) con Cloud Build

El repositorio de código fuente en GitHub (https://github.com/DysorderJack/jardines_del_cerro.git) se encuentra directamente enlazado a un Activador (Trigger) de Google Cloud Build en la rama main. Cada vez que el equipo de desarrollo realiza un git push origin main:

  1. Cloud Build detecta el webhook de GitHub de forma instantánea.
  2. Descarga el código fuente y ejecuta los pasos definidos en cloudbuild.yaml.
  3. Construye la nueva imagen Docker y la etiqueta con el hash SHA del commit.
  4. Sube la imagen a Artifact Registry.
  5. Despliega la nueva revisión en el servicio Cloud Run sin tiempo de inactividad (Zero-Downtime Deployment).
Figura 2.3: Activador oficial de CI/CD en Google Cloud Build vinculado a la rama main de GitHub.

2.6 Seguridad Perimetral, Cifrado HTTPS y Certificados SSL/TLS

Google Cloud Run aprovisiona y renueva automáticamente certificados SSL/TLS emitidos por Google Trust Services. Todo el tráfico hacia https://jardines-del-cerro-976758200291.us-central1.run.app/ viaja cifrado bajo el protocolo TLS 1.3 con algoritmos AES-GCM de 256 bits, garantizando la total privacidad de los datos de pagos, cédulas y comprobantes fiscales.

3. Método Alternativo: Instalación Local / On-Premise (Evaluación)

Para fines de evaluación académica por el docente de la asignatura INF-424 Diseño de Sistemas, o para que un desarrollador pueda realizar modificaciones offline, se detalla el procedimiento riguroso de instalación y puesta en marcha en una computadora local con Windows.

3.1 Prerrequisitos de la Estación de Trabajo

  • Sistema Operativo: Windows 10 u 11 (64-bit), Linux Ubuntu 22.04+ o macOS Ventura+.
  • Python: Versión 3.11.x instalada (marcando la opción "Add Python to PATH" durante la instalación).
  • Git CLI: Instalado para clonar y sincronizar el repositorio.

3.2 Clonación del Repositorio de Código Fuente

Abra una consola de comandos (PowerShell o CMD) y ejecute:

# Clonar repositorio oficial
git clone https://github.com/DysorderJack/jardines_del_cerro.git

# Acceder al directorio raíz del proyecto
cd jardines_del_cerro

3.3 Configuración del Entorno Virtual de Python

Es indispensable crear un entorno virtual aislado para evitar colisiones con librerías del sistema:

# Crear entorno virtual con Python 3.11
python -m venv venv

# Activar en Windows (PowerShell)
.\venv\Scripts\Activate.ps1

# O en Windows (CMD clásico)
.\venv\Scripts\activate.bat

3.4 Instalación de Dependencias (requirements.txt)

Con el entorno virtual activado, instale las librerías necesarias ejecutando:

pip install --upgrade pip
pip install -r sitio_web/backend/requirements.txt

Las dependencias clave instaladas incluyen: fastapi, uvicorn[standard], pydantic, python-dotenv, requests, python-jose[cryptography] y passlib[bcrypt].

3.5 Configuración de Variables de Entorno Locales (.env)

Copie el archivo de ejemplo o cree un archivo .env en la ruta sitio_web/backend/.env:

# Configuración del Servidor Local
PORT=8000
ENVIRONMENT=development
ALLOWED_ORIGINS=http://localhost:8000,http://127.0.0.1:8000

# Base de Datos SQLite
DATABASE_URL=sqlite:///./jardines_del_cerro.db

# Seguridad Criptográfica
SECRET_KEY=clave_secreta_desarrollo_utesa_inf424_jardines_del_cerro_2026
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=480

# Google Gemini AI (Opcional en local: tiene fallback offline)
GEMINI_API_KEY=tu_clave_gemini_api_aqui

# Pasarela PayPal Sandbox
PAYPAL_CLIENT_ID=sandbox_client_id_prueba
PAYPAL_CLIENT_SECRET=sandbox_secret_prueba
PAYPAL_MODE=sandbox

3.6 Inicialización de Base de Datos y Datos Semilla (seed_data.py)

Para cargar el catálogo maestro de 9 niveles, las unidades 101 a 902, los usuarios administrativos, residentes y reportes iniciales, ejecute:

cd sitio_web/backend
python seed_data.py
cd ../..

3.7 Ejecución Mediante Scripts de Automatización Windows (.bat)

El proyecto incluye ejecutables de automatización por lotes para iniciar el backend y el portal web con un solo doble clic desde el Explorador de Archivos de Windows:

  • INICIAR_PROYECTO_COMPLETO.bat: Inicia el servidor FastAPI Uvicorn en segundo plano y abre automáticamente la aplicación web en Microsoft Edge o Google Chrome.
  • INICIAR_BACKEND.bat: Inicia exclusivamente el servidor Uvicorn en el puerto 8000 mostrando la consola de trazas HTTP.

3.8 Comprobación de Servicios Locales

Abra su navegador web y compruebe las siguientes URLs locales:

  • Portal Web Local: http://localhost:8000/
  • Documentación Swagger de la API: http://localhost:8000/docs
  • Esquema OpenAPI JSON: http://localhost:8000/openapi.json

4. Mantenimiento Operativo, Respaldos y Monitoreo

4.1 Política de Respaldos de Base de Datos Relacional SQLite

La base de datos relacional jardines_del_cerro.db almacena el estado completo de unidades, reservas atómicas, usuarios, cuotas de mantenimiento, comprobantes fiscales e-CF y órdenes de trabajo. Para generar una copia de seguridad en caliente sin bloquear las lecturas: 

# Respaldo atómico de SQLite mediante consola
sqlite3 sitio_web/backend/jardines_del_cerro.db ".backup 'respaldo_jardines_$(date +%Y%m%d).db'"

4.2 Monitoreo de Trazas en Tiempo Real con Cloud Logging CLI

Los ingenieros de DevOps y administradores pueden inspeccionar las trazas de producción en tiempo real utilizando Google Cloud SDK:

# Ver logs en vivo del servicio Cloud Run
gcloud beta run services logs tail jardines-del-cerro --region=us-central1

# Filtrar únicamente excepciones y errores HTTP 5xx
gcloud logging read "resource.type=cloud_run_revision AND severity>=ERROR" --limit=20

4.3 Matriz de Solución de Problemas Frecuentes (Troubleshooting)

Síntoma / Incidencia Causa Raíz Identificada Procedimiento de Solución Inmediata
Puerto 8000 ocupado en local Una instancia previa de Uvicorn o Node.js no se cerró correctamente. Ejecute en PowerShell: Stop-Process -Id (Get-NetTCPConnection -LocalPort 8000).OwningProcess -Force o cambie el puerto a 8001 en el archivo .env.
Error 404 Not Found en Cloud Run URL errónea o región incorrecta seleccionada en la barra de navegación. Verifique acceder a la región us-central1: https://jardines-del-cerro-976758200291.us-central1.run.app/.
Activador de Cloud Build no compila Permisos insuficientes en la cuenta de servicio de Cloud Build para Artifact Registry. En la consola de IAM de Google Cloud, asigne el rol "Administrador de Artifact Registry" y "Administrador de Cloud Run" a la cuenta 976758200291@cloudbuild.gserviceaccount.com.
Falla de comunicación con Gemini IA Cuota de API Key agotada o bloqueo de red saliente. El sistema conmuta de forma transparente al Motor Local Precompilado de Fallback Offline, respondiendo las consultas de los usuarios sin interrupción del servicio.
